1. Общие положения

В документе описаны сценарии тестирования кассового ПО в рамках:

  • Бизнес-логики программы "СберСпасибо"

  • Варианта интеграции через Purchase-API (актуальный API Бонусного процессинга АО "ЦПЛ")

  • Недоступность ПЦ не влияет на кассовые торговые операции (начисление и списание бонусов возможно только в случае оплаты чека банковской картой Сбербанка)

  • Для КПО отсутствует возможность запроса информации по бонусному балансу клиента

  • В случае если КПО поддерживает сторонние программы лояльности: совместно с партнером должны быть зафиксированы тесты, проверяющие согласованные бизнес-требования до начала тестирования интеграции

2. Тестовое окружение

  • Параметры инфраструктуры (partnerId, servicePointExtId, terminal) предоставляются сотрудниками АО "ЦПЛ"

  • На этапе тестирования необходимо использовать индивидуальные параметры инфраструктуры: каждый партнер получает свои параметры тестового окружения в demo-комплексе "Бонусный процессинг АО "ЦПЛ"
Корневая точка сервисов Purchase-API (зависит от типа подключения: терминальное или хостовое):

https://loystg-api.demo.spasibobonus.ru:4452/purchase-sber-terminal/v1
https://loystg-api.demo.spasibobonus.ru:4452/purchase-sber-host/v1

3. Порядок прохождения тестирования

Сценарии, по которым должно выполняться тестирование интеграции, приведены в разделе Сценарии тестирования.

Краткое описание процесса

  1. Партнёр выполняет все пункты тестирования с картой А1 и сообщает о завершении сотрудникам АО "ЦПЛ"

  2. Сотрудники АО "ЦПЛ" вносят изменения в настройки тестовой карты на стороне ПЦ и переводят её в состояние R1

  3. Партнёр выполняет все пункты тестирования с картой R1 и сообщает о завершении сотрудникам АО "ЦПЛ"

  4. Сотрудники АО "ЦПЛ" вносят изменения в настройки тестовой карты на стороне ПЦ и переводят её в состояние A2

  5. Партнёр выполняет все пункты тестирования с картой A2 и присылает результаты на проверку

  6. Сотрудники АО "ЦПЛ" выполняют проверку результатов

    1. если есть ошибки или замечания, то:

      1. Сотрудники АО "ЦПЛ" передают список замечаний с комментариями по их исправлению

      2. Партнёр вносит исправления и присылает повторно результаты на проверку

    2. если ошибок и замечаний нет, то тестирование считается успешным.

3.1. Данные необходимые для проверки на стороне "Бонусный процессинг АО "ЦПЛ"

Все данные по прохождению сценариев тестирования следует фиксировать в рамках html-документа с веб-формами "Результаты прохождения тестирования.html", который передаётся партнёру сотрудниками АО "ЦПЛ" перед началом тестирования.

Тест № 6. Ошибки связи

Имитация недоступности ПЦ может быть имитирована на кассе, например, отключением сетевого кабеля в определённый момент выполнения сценария теста.

Если по каким-либо причинам такой возможности нет, то для прохождения тестирования в запросах следует использовать следующие параметры тестового окружения, которые позволят выполнить имитацию недоступности ПЦ:

Для теста 6.1:

  • PartnerId: 11802504

  • ServicePointExtId: to_purchase

  • Terminal: term_purchase

Для теста 6.2:

  • PartnerId: 11802509

  • ServicePointExtId: to_bonusSpend

  • Terminal: term_bonusSpend

Для теста 6.3 и 6.3.1:

  • PartnerId: 11802514

  • ServicePointExtId: to_confirmation

  • Terminal: term_confirmation

# API документа «Инцидент»

Описание подключения к 1С:ITILIUM (`ITILIUMPROF`) для автоматического создания документа `Документ.Инцидент`, чтения его данных, изменения реквизитов и смены состояния.

Канал интеграции — HTTP-сервис `ExternalSystemAPI`. Это штатный сервис обмена с внешними системами. Веб-сервис `IT_Mobile` и HTTP-сервис веб-портала для этого сценария не используются: они завязаны на сеанс потребителя услуг и лицензию портала или мобильного приложения.

## Что уже опубликовано и чего не хватает

| Операция | Метод | Статус |
| --- | --- | --- |
| Справочники для заполнения ссылок | `POST /hs/externalapi/get…` | Есть |
| Список обращений | `POST /hs/externalapi/getIncidentsList` | Есть |
| Карточка обращения | `POST /hs/externalapi/extGetDetailIncidentInfo` | Есть |
| Файл вложения | `POST /hs/externalapi/extGetFileData` | Есть |
| Смена состояния | `POST /hs/externalapi/changeIncidentState` | Есть |
| Создание обращения | `POST /hs/externalapi/createIncident` | Нужно добавить |
| Изменение реквизитов | `POST /hs/externalapi/updateIncident` | Нужно добавить |

Методы создания и изменения ниже заданы в том же стиле, что и действующие методы сервиса: `POST`, JSON, идентификаторы ссылок — UUID. Пока этих шаблонов URL в метаданных нет, вызов вернёт 404.

## Подключение

Базовый URL публикации:

```text
http(s)://<сервер>/<имя-публикации>/hs/externalapi
```

Аутентификация — пользователь информационной базы, под которым публикуется HTTP-сервис (обычно Basic). У пользователя должно быть право на вызываемый метод `HTTPService.ExternalSystemAPI`. Выборка документов и справочников идёт с ограничением прав (`ВЫБРАТЬ РАЗРЕШЕННЫЕ`): интеграционный пользователь видит только те обращения, которые ему разрешены.

Перед вызовами в базе должно быть включено:

- константа `ВнешнееАПИДляРаботыСОбращениями` = Истина;
- действующая лицензия 1С:ITILIUM (проверка `оз_НастройкаФорм`).

Если константа выключена или лицензия не получена, сервис отвечает HTTP 200 и телом:

```json
{ "Error": "Сервис получения данных внешними системами отключен в параметрах системы. Обратитесь к администратору." }
```

Сеансы HTTP-сервиса переиспользуются (`ReuseSessions = AutoUse`, `SessionMaxAge = 20`).

## Соглашения по JSON

- Заголовок запроса: `Content-Type: application/json; charset=utf-8`.
- Все скалярные поля запроса передаются строками. Разбор действующих методов читает только `ТипЗначенияJSON.Строка`: число, булево и `null` игнорируются.
- UUID — строка уникального идентификатора 1С, с дефисами, как её возвращает `Строка(Ссылка.УникальныйИдентификатор())`.
- Несколько UUID в фильтрах списка — одна строка, значения через запятую.
- Даты на вход — строка, которую принимает 1С-функция `Дата()`. Надёжный формат: `yyyyMMddHHmmss`, например `20261119163100`. Допустима дата без времени: `yyyyMMdd`.
- Даты на выход — `Строка(Дата)` сеанса информационной базы, обычно `ДД.ММ.ГГГГ ЧЧ:ММ:СС`.
- Булевы признаки в ответах — строки `"true"` / `"false"`.
- Имя свойства в запросе не чувствительно к регистру.
- Успех и ошибка бизнес-логики приходят с HTTP 200. Ошибку нужно определять по телу. Транспортные ошибки (401, 403, 404, 500) означают публикацию, права или отсутствие метода.
- Бизнес-ошибка действующих методов:

```json
{ "isError": true, "ErrorText": "Текст ошибки" }
```

Пустое тело при HTTP 200 — не ошибка. Так отвечает успешная смена состояния.

## Справочники

Все методы — `POST`. Тело можно передать пустым объектом `{}`, кроме `getServices`.

| Метод | Тело | Ответ, массив |
| --- | --- | --- |
| `/getStates` | `{}` | `States[]`: `State`, `StateUuid`, `StateCode`. Справочник `СостоянияИнцидентов` |
| `/getClients` | `{}` | `Clients[]`: `Client`, `ClientUuid`, `ClientCode`. Справочник `Клиенты` |
| `/getInitiators` | `{}` | инициаторы, справочник `ИТ_КонтактныеЛица` |
| `/getEmployers` | `{}` | сотрудники, справочник `Сотрудники` |
| `/getWorkgroups` | `{}` | рабочие группы, справочник `ОрганизационныеПодразделения` |
| `/getCategories` | `{}` | категории, справочник `ИТ_Категории` |
| `/getPriorities` | `{}` | приоритеты, справочник `Приоритеты` |
| `/getSources` | `{}` | каналы связи, справочник `ИТ_КаналыСвязи` |
| `/getTypes` | `{}` | типы обращений, справочник `ИТ_ТипыИнцидентов` |
| `/getClosingCodes` | `{}` | коды закрытия |
| `/getServices` | `{ "servClientUuid": "<UUID клиента>" }` | услуги, доступные клиенту. Без UUID — общий список |
| `/getServiceComponents` | `{}` | состав услуг, справочник `СоставУслуг` |

Пример:

```http
POST /hs/externalapi/getStates
Content-Type: application/json

{}
```

```json
{
  "States": [
    { "State": "Зарегистрирован", "StateUuid": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee", "StateCode": "000000001" }
  ]
}
```

UUID из этих ответов подставляются в создание, изменение и смену состояния. Наименование для записи не используется.

## Список обращений

`POST /hs/externalapi/getIncidentsList`

Тело — объект фильтров. Все поля необязательны. Несколько условий объединяются по `AndOr`: `AND` (по умолчанию) или `OR`.

| Поле | Реквизит `Документ.Инцидент` | Отбор |
| --- | --- | --- |
| `startFrom` | — | Сколько записей пропустить. Строка с числом, по умолчанию `0` |
| `count` | — | Размер страницы. Строка с числом. `0` — без ограничения |
| `AndOr` | — | `AND` или `OR` |
| `number` | `Номер` | Равенство |
| `date` | `Дата` | Равенство |
| `dateStart`, `dateEnd` | `Дата` | Период, одна граница или обе |
| `topic` | `ТемаОбращения` | Подстрока |
| `description` | `Описание` | Подстрока, первые 1000 символов |
| `solution` | `Замечания` | Подстрока, первые 1000 символов |
| `stateUuid` | `Состояние` | Список UUID через запятую |
| `clientUuid` | `Клиент` | Список UUID |
| `initiatorUuid` | `КонтактноеЛицо` | Список UUID |
| `responsibleUuid` | `Ответственный` | Сотрудник или организационное подразделение |
| `workgroupUuid` | `ОргПодразделение` | Список UUID |
| `operatorUuid` | `Оператор` | Список UUID |
| `curatorUuid` | `Куратор` | Список UUID |
| `categoryUuid` | `Категория` | Список UUID |
| `priorityUuid` | `Приоритет` | Список UUID |
| `sourceUuid` | `КаналСвязи` | Список UUID |
| `serviceUuid` | `Услуга` | Список UUID |
| `serviceComponentUuid` | `КомпонентаУслуги` | Список UUID |
| `typeUuid` | `Тип` | Список UUID |
| `closingCodeUuid` | `КодЗакрытия` | Список UUID |

Отбор `mass` и одновременный период `deadlineDateStart` + `deadlineDateEnd` в текущем коде запроса не дают ожидаемого условия. Для этих признаков читайте карточку.

Ответ:

```json
{
  "Incidents": [
    {
      "linkUuid": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
      "number": "000000123",
      "date": "19.11.2026 16:31:00",
      "state": "Зарегистрирован",
      "stateUuid": "bbbbbbbb-cccc-dddd-eeee-ffffffffffff",
      "topic": "Не печатает принтер",
      "description": "Текст описания",
      "availableStates": [
        { "state": "В работе", "stateUuid": "cccccccc-dddd-eeee-ffff-000000000000" }
      ]
    }
  ]
}
```

`availableStates` — состояния, в которые сценарий обработки разрешает перейти из текущего. Именно их можно передать в `changeIncidentState`.

Сортировка — по номеру. Пагинация читает первые `startFrom + count` записей и отбрасывает начало выборки на сервере. Большой `startFrom` лучше не использовать: отбирайте периодом `dateStart` / `dateEnd` или номером.

## Смена состояния

`POST /hs/externalapi/changeIncidentState`

Состояние — справочник `СостоянияИнцидентов`. Прямая запись реквизита `Состояние` допустима только в состояние, которое сценарий обработки (`СценарийОбработки` + `Тип`) разрешает из текущего. Список разрешённых значений — `availableStates` списка или `AvailaibleStates` карточки.

```json
{
  "docUuid": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
  "newStateUuid": "cccccccc-dddd-eeee-ffff-000000000000"
}
```

Поведение действующего метода:

| Ситуация | Тело ответа |
| --- | --- |
| Переход разрешён, документ записан | HTTP 200, пустое тело |
| `docUuid` не передан | `{ "isError": true, "ErrorText": "Документ не найден" }` |
| `newStateUuid` не передан | `{ "isError": true, "ErrorText": "Состояние не найдено" }` |
| Запись вызвала исключение | `{ "isError": true, "ErrorText": "<описание>" }` |
| UUID состояния не входит в разрешённые переходы | HTTP 200, пустое тело, реквизит не меняется |

Пустой успешный ответ не отличает выполненный переход от запрещённого. После вызова читайте карточку и сравнивайте `stateUuid`.

Обязательные поля сценария (в том числе дополнительные) проверяются при записи документа. Если переход их требует, а они пустые, запись падает с текстом сообщения пользователю в `ErrorText`.

## Создание обращения

Метод к реализации: `POST /hs/externalapi/createIncident`.

Назначение — зарегистрировать `Документ.Инцидент` от имени интеграционного пользователя, с явным клиентом и инициатором, без сеанса веб-портала.

Алгоритм на стороне 1С:

1. Проверить константу `ВнешнееАПИДляРаботыСОбращениями` и лицензию так же, как в `changeIncidentState`.
2. Если передан `externalID` и документ с таким `ВнешнийID` уже есть, новый не создавать. Вернуть карточку существующего и `"created": "false"`.
3. `Документы.Инцидент.СоздатьДокумент()`, `Заполнить(Неопределено)`.
4. Записать переданные реквизиты. Ссылочные поля получать через `ПолучитьСсылку(Новый УникальныйИдентификатор(...))` и проверять, что объект существует.
5. Если передан `serviceComponentUuid` и не передан `serviceUuid`, `Услуга` = владелец состава услуги.
6. Пустые `Приоритет`, `Тип`, `Ответственный`, `ОргПодразделение`, `СценарийОбработки`, `Состояние`, `КаналСвязи`, `ЧасовойПоясДокумента`, `ДатаНачалаРегистрации` заполнять теми же правилами, что форма обращения: константа `ИТ_ПриоритетИнцидента`, константа `ИТ_ТипИнцидента` или тип состава услуги, ответственный по услуге, сценарий по составу услуги и клиенту, начальное состояние сценария.
7. `Состояние` из запроса принимать только если оно входит в начальные состояния сценария. Иначе оставлять состояние по умолчанию.
8. `Записать()` с проведением правил обработки. Сообщения пользователю вернуть в `ErrorText`.
9. Ответ — карточка в формате `extGetDetailIncidentInfo` плюс признак `created`.

Обязательные поля запроса: `clientUuid`, `initiatorUuid`. В метаданных у реквизитов `Клиент` и `КонтактноеЛицо` проверка заполнения «показывать ошибку». Инициатор должен принадлежать указанному клиенту (`КонтактноеЛицо.Владелец = Клиент`).

Рекомендуемые поля: `topic`, `description`, `externalID`. `externalID` — ключ идемпотентности внешней системы.

```json
{
  "externalID": "MONITOR-2026-00042",
  "clientUuid": "aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee",
  "initiatorUuid": "bbbbbbbb-cccc-dddd-eeee-ffffffffffff",
  "topic": "Недоступен сервис печати",
  "description": "Очередь печати не принимает задания с 16:20.",
  "serviceComponentUuid": "cccccccc-dddd-eeee-ffff-000000000000",
  "categoryUuid": "dddddddd-eeee-ffff-0000-111111111111",
  "priorityUuid": "eeeeeeee-ffff-0000-1111-222222222222",
  "sourceUuid": "ffffffff-0000-1111-2222-333333333333",
  "responsibleUuid": "00000000-1111-2222-3333-444444444444",
  "workgroupUuid": "11111111-2222-3333-4444-555555555555",
  "configurationItems": [
    "22222222-3333-4444-5555-666666666666"
  ]
}
```

Успех:

```json
{
  "created": "true",
  "uuid": "99999999-aaaa-bbbb-cccc-dddddddddddd",
  "number": "000000124",
  "state": "Зарегистрирован",
  "stateUuid": "bbbbbbbb-cccc-dddd-eeee-ffffffffffff",
  "externalID": "MONITOR-2026-00042"
}
```

Остальные поля карточки возвращаются вместе с этими. Повтор того же `externalID` возвращает тот же `uuid` и `"created": "false"`.

Ошибки — `{ "isError": true, "ErrorText": "..." }`:

- не заполнены клиент или инициатор;
- UUID не найден или ссылка помечена на удаление;
- инициатор не относится к клиенту;
- не заполнены обязательные дополнительные поля начального состояния;
- исключение при записи.

## Изменение реквизитов

Метод к реализации: `POST /hs/externalapi/updateIncident`.

Меняются только поля, которые есть в JSON. Отсутствующее поле не очищает реквизит. Чтобы очистить строковый реквизит, передайте пустую строку. Ссылку этим методом не очищать: для смены ссылки передаётся новый UUID.

Идентификация документа — ровно одно из полей:

- `uuid` — ссылка документа;
- `externalID` — реквизит `ВнешнийID`. Если найдено больше одного документа, вернуть ошибку.

`Состояние` этим методом не меняется. Смена статуса — только `changeIncidentState`, чтобы не обойти правила перехода.

```json
{
  "uuid": "99999999-aaaa-bbbb-cccc-dddddddddddd",
  "topic": "Недоступен сервис печати, корпус Б",
  "description": "Уточнение: не печатает только третий этаж.",
  "solution": "Перезапущен диспетчер печати.",
  "priorityUuid": "eeeeeeee-ffff-0000-1111-222222222222",
  "responsibleUuid": "00000000-1111-2222-3333-444444444444",
  "closingCodeUuid": "33333333-4444-5555-6666-777777777777"
}
```

Успех — карточка документа после записи, `"updated": "true"`. Ошибка записи и сообщения обязательных полей — в `ErrorText`.

Поля, которые метод принимает:

| Поле запроса | Реквизит | Тип |
| --- | --- | --- |
| `topic` | `ТемаОбращения` | строка |
| `description` | `Описание` | строка |
| `solution` | `Замечания` | строка |
| `commentaryOnTheNotice` | `КомментарийКИзвещению` | строка |
| `clientUuid` | `Клиент` | `Справочник.Клиенты` |

## Сценарий автоматического создания

1. Один раз прочитать справочники и сохранить UUID клиента, инициатора, состава услуги, приоритета, канала связи и состояний.
2. `createIncident` с устойчивым `externalID` внешней заявки.
3. Сохранить `uuid` и `number` из ответа.
4. Уточнения по ходу работы передавать в `updateIncident`.
5. Перед сменой статуса прочитать `AvailaibleStates`.
6. `changeIncidentState` с `stateUuid` из этого списка.
7. Повторно прочитать карточку и убедиться, что `stateUuid` изменился.

Повтор шага 2 с тем же `externalID` после реализации идемпотентности возвращает уже созданный документ.

## Другие опубликованные интерфейсы

Их можно не подключать для этого сценария.

`HTTP-сервис WEBPortal_v2`, корень `web-portal-api`, метод `POST /addNewIncident` создаёт обращение, но требует лицензию веб-портала. Инициатор берётся из контактного лица текущего сеанса, канал связи фиксируется как веб-портал. Произвольного клиента и внешний идентификатор метод не принимает.

Веб-сервис `IT_Mobile`, пространство имён `http://www.mobile.itilium.org`, WSDL публикации `.../ws/IT_Mobile.1cws?wsdl`. Операции `NewIncWithoutTemplate`, `NewIncOnTemplate` и `UpdateDoc` рассчитаны на мобильное приложение и выполняются в привилегированном режиме сеанса. Для внешней системы используйте HTTP-сервис `externalapi`.

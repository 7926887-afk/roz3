ТЗ. Команды формы элемента справочника эвИсточникиЗаказов

Команды формы элемента справочника эвИсточникиЗаказов — это ручной обмен с порталом текущего источника. В новой конфигурации их нужно реализовать так же: тонкие обработчики формы и серверные процедуры модуля обмена.

1. Общие правила

Кнопки — гиперссылки в группе «Актуализация данных». Видимость задаёт клиентская процедура при открытии формы и при изменении реквизита Вид.

Команда                              МегаАптека   Ютека   Асна   прочие виды
Отправить аптеку в сервис            да           да      нет    нет
Проверить статус аптеки              да           нет     нет    нет
Удалить аптеку из сервиса            да           да      нет    нет
Выполнить связки АСНА                нет          нет     да     нет
Отправить файл каталога АСНА         нет          нет     да     нет
Полная выгрузка остатков             да           да      да     нет

Настройки подключения берутся из ПолучитьПараметрыПодключенияКПорталу(Вид, Активный): все элементы справочника с тем же видом и тем же признаком Активный, плюс регистр эвНастройкиAPIИсточникаЗаказов (Адрес, auth_token, merchant, для АСНА ещё ЛогинФТП, ПарольФТП, АдресФТП). Пустые Адрес, auth_token или merchant пропускаются с сообщением «Настройки API не указаны!».

Тело пакета аптеки строится по реквизитам открытого элемента, а не по каждой найденной настройке. Успешный ответ не записывает элемент: меняется только Объект.Активный на форме, пользователь сохраняет сам.

2. Пакет аптеки

Общий для МегаАптеки и Ютеки. Контактные данные склада читаются из контактной информации магазина склада.

Поле JSON          Источник
id                 XML-представление Склад
region             areaValue фактического адреса магазина
city               city, а если пусто — areaValue
address            хвост представления адреса от последнего вхождения города, без префикса «Город,»
brand              константа ЭВАЛАР
latitude           Широта элемента
longitude          Долгота элемента
phone              телефон магазина
schedule           ГрафикРаботы
ogrn               ОГРН организации склада
email              адрес электронной почты магазина
is_deleted         Ложь при отправке, Истина при удалении

Адрес: вид ФактАдресМагазина, тип «Адрес». Телефон: вид ТелефонМагазина. Почта: тип «Адрес электронной почты», без отбора по виду. JSON адреса разбирается через УправлениеКонтактнойИнформациейСлужебный.JSONВКонтактнуюИнформациюПоПолям. Если фактического адреса нет, HTTP-запрос не выполняется и сообщение пользователю не выводится.

3. Отправить аптеку в сервис

Клиент. Если Склад пустой — сообщение «Укажите склад» и выход.

МегаАптека: POST {Адрес}/stores. Заголовки: Content-Type: application/json, merchant-code, auth-token. Тело { list: [ аптека ] }, is_deleted = Ложь.

Ютека: PUT {Адрес}/stores?mc={merchant}. Заголовки: Content-Type: application/json, auth_token. То же тело.

Код 200: сообщение «Данные в сервисе актуализированы!», Активный = Истина. Иной код: Активный = Ложь, запись в журнал регистрации. Если в ответе есть message, его показать пользователю. У Ютеки после этого обработка остальных настроек прекращается. Исключение HTTP пишется в журнал, форма не падает.

4. Удалить аптеку из сервиса

Тот же сценарий, что у отправки, с is_deleted = Истина. Склад обязателен. Проверка статуса для этой команды не вызывается. При коде 200 признак Активный тоже устанавливается в Истина.

5. Проверить статус аптеки

Только МегаАптека. Склад на клиенте не проверяется.

GET {Адрес}/stores, те же заголовки, что у отправки, параметр store_id = XML-представление склада. При коде 200 каждая структура из list выводится пользователю строками «ключ = значение». Иной код пишется в журнал. Для Ютеки обработчик пустой, кнопка скрыта.

6. Выполнить связки АСНА

Вопрос: «Связки загружать спустя не менее чем через 3 часа, после отправки каталога! Продолжить?». Отказ прерывает команду.

Сервер вызывает загрузку связок по всем активным источникам вида Асна: GET {Адрес}/v5/references/goods_links?names=false, заголовок Authorization: Bearer {token}. Пустой токен и ответ 401 обновляют токен и повторяют запрос. Ответ-массив записывается в регистр связок: sku — GUID номенклатуры, код АСНА — код связки. Некорректный GUID пропускается.

7. Отправить файл каталога АСНА

Вопрос: «Каталог выгружать не чаще 1 раза в неделю! Продолжить?».

Клиент проверяет наличие C:\Program Files (x86)\WinSCP\WinSCP.exe. Если файла нет — сообщение и выход.

Сервер по активным источникам Асна, у которых заполнены параметры FTP, формирует DBF остатков склада (кодировка ANSI):

Поле       Длина   Содержание
ID         36      XML-представление номенклатуры
Name       100     представление
Producer   150     производитель
Country    60      страна происхождения
EAN        150     штрихкоды EAN длиной 12 или 13 без характеристики, через запятую

Позиция без производителя или без штрихкода пропускается с сообщением. Двоичные данные кладутся во временное хранилище. Возврат: ЛогинФТП, ПарольФТП, АдресФТП. Пустая строка означает, что склад выгрузки не найден; клиент сообщает: «В источнике заказов Асна не указан склад выгрузки остатков».

Клиент записывает DBF во временный файл и запускает WinSCP синхронно: SFTP, put в \goods.dbf с -delete. Лог показывается пользователю. В Комментарий пишется «Отправка каталога {текущая дата}», форма помечается модифицированной.

8. Полная выгрузка остатков

Без вопроса. Выгрузка по всем активным источникам данного вида, не только по открытому элементу. Признак полной выгрузки — Истина (все остатки, а не дельта).

МегаАптека: выгрузка остатков и цен, регистр сведений эв_СвободныеОстаткиДляПорталаМегааптека.

Ютека: то же, регистр эв_СвободныеОстаткиДляПорталаЮтека.

Асна: перед выгрузкой повторно загружаются связки и отправляется отчёт о продажах, затем остатки и цены. Позиции с нулевой ценой или нулевым кодом АСНА не отправляются.

Если у вида нет активного источника со складом и видом цен, процедура завершается без сообщения.

9. Размещение в новой конфигурации

В модуле формы остаются видимость, вопросы, проверка склада и запуск WinSCP. В серверный модуль обмена выносятся:

- сбор пакета аптеки;
- отправка и удаление аптеки (один метод, параметр Удалить);
- проверка статуса МегаАптеки;
- загрузка связок АСНА;
- формирование DBF каталога и возврат параметров FTP;
- полная выгрузка остатков с диспетчеризацией по виду.

HTTP выполняется через КоннекторHTTP (PostJson, PutJson, GetJson). Ошибки транспорта пишутся в журнал регистрации и не прерывают обход остальных настроек, кроме раннего выхода Ютеки по полю message.

10. Приёмка

1. Смена Вид сразу показывает только команды этой строки матрицы.
2. МегаАптека: отправка делает POST /stores и при 200 включает Активный без записи элемента.
3. Удаление шлёт тот же пакет с is_deleted = true.
4. Проверка статуса печатает поля ответа только для МегаАптеки.
5. Ютека: PUT /stores?mc=...; пустой склад блокирует отправку и удаление.
6. АСНА: связки и каталог стартуют только после подтверждения; без WinSCP каталог не уходит.
7. После каталога в комментарии есть дата отправки, форма модифицирована.
8. Полная выгрузка для АСНА сначала обновляет связки.
9. Пустые настройки API дают сообщение и не вызывают HTTP.

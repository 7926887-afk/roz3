ОПИСАНИЕ API ПОРТАЛА БУС (ЭВАЛАР)
================================================================================
Назначение файла: исходные данные для промта на реализацию обмена в другой конфигурации 1С.
Дата сборки: 2026-09-29.

В заказе покупателя есть поле ВидЗаказа. Для каждого портала будет создан свой вид заказа. В нем мы укажем 
поле Портал с типом перечисление эв_ВидыИсточниковЗаказа.
В виде заказа будет прописан перечен Статусов заказов а табличной части Состояния. 

Состояния заказов имеют код на партале. На каждом портале свой код статуса. 
Связь состояний заказа и значений кодов статусов заказа на портале задаются в регистре сведений: эв_КодыСтатусовПорталов,
где ВидСтатуса это состояние заказа покупателя. И вид источника заказа.

Результаты каждого HTTP запроса фиксируются в регистре сведений эв_ЛогиHTTPПорталов.

Целевая формулировка для промпта:
  Реализовать обмен с БУС Эвалар: инкремент и полную выгрузку остатков (и опционально цен),
  загрузку новых заказов с подтверждением получения, обмен статусами заказов (отменен, выполнен).

================================================================================
1. ОБЩИЕ СВЕДЕНИЯ
================================================================================

Портал: Эвалар (перечисление эв_ВидыИсточниковЗаказа.Эвалар).

Сценарии, которые нужно реализовать:
1) Полная выгрузка остатков и цен.
2) Инкрементальная выгрузка остатков и цен (только изменения).
3) Загрузка заказов с портала и подтверждение получения.

Смежный сценарий:
4) Отправка статусов заказов на портал.

Базовый URL, токен и код мерчанта хранятся в регистре сведений эв_НастройкиAPIИсточникаЗаказов
в разрезе источника заказов (справочник эвИсточникиЗаказов):
  - Адрес       — базовый URL API без завершающего слэша, например https://api.example.com
  - auth_token  — токен авторизации
  - merchant    — код мерчанта (merchant-code)

Источник заказов (справочник эв_ИсточникиЗаказов) для МегаАптеки должен содержать:
  - Вид      = Эвалар
  - Активный = Истина
  - Склад    — склад аптеки (его UUID уходит в API как store_id)
  - ВидЦен   — вид цены, которым заполняется price

Проверка готовности настроек (ДанныеПорталаКорректны):
  Адрес, auth_token и merchant не должны быть пустыми.

Формат обмена: JSON, кодировка UTF-8.
Content-Type: application/json

Идентификаторы:
  - store_id  — UUID склада 1С (XMLСтрока(Склад), 36 символов).
  - id товара — UUID номенклатуры 1С (XMLСтрока(Номенклатура)), НЕ характеристики.
  - id заказа — числовой external_id портала.

Заказы всегда идут на PHP БУС (Bitrix) по HTTPS:
  хост = домен из АдресСайта узла обмена (часть до первого «/» начиная с позиции 10).
  Пример адреса узла: asevalar.ru/local/tools/1c_exchange/exchange_remain_as_sokol.php
  Домен соединения:   asevalar.ru

Полная vs инкремент задаётся реквизитом узла ВыгружатьИзменения:
  ВыгружатьИзменения = Истина  → инкремент  (ПолнаяВыгрузка = Ложь)
  ВыгружатьИзменения = Ложь    → полная     (ПолнаяВыгрузка = Истина)

2.1. Инкрементальные остатки + загрузка заказов
Регламентное задание: эв_ОбменОстаткамиИЗаказамиПорталов
Метод: эв_ОбменСПорталамиСервер.ВыполнитьИнкрементальныйОбмен
Расписание метаданных: каждые 120 секунд, с 08:00 до 23:30.
Выполняется только на боевой базе.

Порядок:
  1) эв_ОбменСПорталамиСервер.ВыполнитьИнкрементальныйОбмен → внутри ВыполнитьЗагрузкуЗаказовИзЭвалар()
  2) эв_ВыгрузитьОстаткиЦеныНаПорталМегааптека(Ложь)

2.2. Полные остатки
Регламентное задание: эв_ОбменОстаткамиПолнымиПорталов
Метод: эвОбменСПорталамиСобытия.ВыполнитьОбменСПорталамиПолная
Расписание метаданных: 23:35–23:45.
Вызов: эв_ВыгрузитьОстаткиЦеныНаПорталЭвалар(Истина)

2.3. Очередь статусов
Регламентное задание: эв_ОбработкаОчередиСтатусовПорталов
Метод: ВыполнитьОбработкуОчередиСтатусовПорталов → ОтправитьСтатусЗаказаЭвалар
Расписание: каждые 30 секунд, с 08:00 до 23:00.

Код статуса для портала берётся в регистре сведений: эв_КодыСтатусовПорталов,
Статусы отправляются через очередь в регистре эв_ОчередьОтправкиСтатусовЗаказов.

Текущий статус при успешной отправке на портал фиксируется в регистре эв_ИсторияСтатусовЗаказов.

1. АВТОРИЗАЦИЯ
================================================================================

1.1. PHP БУС (заказы и статусы)

Отдельного OAuth нет. HTTPS-соединение с доменом сайта.
Все POST через ОтправитьHTTPЗапрос:

  Content-Type: application/json;
  Authorization: Bearer 9296bc206692e0b341b089dd30f25c5d
  (токен в модуле не храним, берем из настроек)

Тело: JSON структуры или массива (ЗаписатьJSON).
Метод: HTTP POST (ОтправитьДляОбработки).
Ответ: JSON, читается в Соответствие/Массив (ПрочитатьJSON(..., Истина)).
Таймаут соединения: 12 с, SSL OpenSSL.

АвторизацияВыполнена / ПолучитьСоединениеССервером только открывают HTTPСоединение,
логина/пароля на сайте нет.

1.2. Микросервис остатков/цен

  Content-Type: application/json;
  SecureToken:  iM,dxBv:MuuKax1#C!sD
  (зашит в модуле)

Хост = АдресСайта узла целиком (без разбора пути).
HTTP, порт 80, БЕЗ SSL, таймаут 120 с.

1.3. Старый PHP остатков (ВыгрузитьОстаткиТоваров)

  Content-Type: application/x-www-form-urlencoded;
  тело при этом JSON-строка (не form-поля).
  token в JSON: hycAM5csKyduRxDJ7QdJ3ThLqU2ZHBYH
  HTTPS SSL, таймаут 120 с.
  Успех: в теле ответа есть подстрока SUCCESS.

В другой конфигурации токены лучше вынести в настройки, не хардкодить.


================================================================================
2. ВЫГРУЗКА ОСТАТКОВ (АКТУАЛЬНЫЙ КОНТУР — МИКРОСЕРВИС)
================================================================================

Процедуры: ВыгрузитьОстаткиТоваровВМикроСервис, ПолучитьОстаткиДляСайтаБУС.
{storeId} = ИдентификаторКаталога узла.

2.1. Остатки

Метод: POST
URL:   http://{АдресСайта}/amount/{storeId}
Успех: HTTP 200. Иной код — прерывание всей выгрузки (снапшот не обновляется).

Тело: JSON-массив порциями по 10 позиций:

[
  { "product": "<UUID номенклатуры>", "amount": <целое количество> }
]

product = Строка(УникальныйИдентификатор номенклатуры).
amount  = Цел(доступный остаток). Может быть 0 (обнуление).
Позиция с Цена=0 И остаток>0 в пакет НЕ попадает.

2.2. Цены (если ВыгружатьЦены = Истина)

Метод: POST
URL:   http://{АдресСайта}/price/{storeId}
Успех: HTTP 200.

Тело, те же порции по 10:

[
  {
    "product": "<UUID номенклатуры>",
    "price": <число>,
    "vat_percentage": <ставка НДС для выгрузки или -1>
  }
]

vat_percentage:
  БезНДС → в коде сначала -1, затем для СтруктурыПредложения всё равно пишется
  результат ветки (для БезНДС остаётся -1).
  Иначе: УчетНДС.СкорректироватьСтавкуНДС + ОбменССайтомРТ.ПолучитьПоСтавкеНДСЗначениеДляВыгрузки.

Цена: если заполнена «Интернет цена (Сокол)» — она, иначе минимальная цена вида цен узла.

В исходнике между остатками и ценами пустой цикл «подождать 15 секунд»
(фактически no-op: Пока ТекущаяДата() <= КонПериода Цикл Продолжить).

2.3. Полная vs инкрементальная — один и тот же HTTP

Портал не различает полную и дельту методом. Разница только в составе массива
(что отобрала 1С). Оба режима бьют POST /amount/{storeId} одинаковым телом.

Отбор ПолучитьОстаткиДляСайтаБУС:

Фактический остаток:
  РН ТоварыНаСкладах.Остатки, склад = Магазин.СкладПродажи,
  Характеристика.ор_СрокГодности > конец текущего дня + 1 день,
  свободный остаток (Количество − Резерв) >= 1,
  затем сумма по номенклатуре (характеристики схлопываются).

Снапшот последней успешной отправки:
  РС фтм_СвободныеОстаткиДляСайта (Номенклатура, Склад, ДоступныйОстаток, Цена, ДатаОбновления).

В пакет попадают три множества (ОБЪЕДИНИТЬ):
  1) есть в учёте и в снапшоте:
       полная: все;
       инкремент: только если остаток учёта <> остаток снапшота;
  2) есть в учёте, нет в снапшоте — всегда (новые);
  3) есть в снапшоте, нет в учёте — amount=0:
       полная: все такие;
       инкремент: только если снапшот.ДоступныйОстаток > 0.

После HTTP 200 по всем порциям снапшот перезаписывается по всей выборке
(включая обнуления). Если хоть одна порция не 200 — снапшот не пишется.

Особенности цены в запросе:
  вид цен из отбора узла (ТипЦены);
  для ценовой группы «ЭВАЛАР» цена с пустой характеристики, если нет цены по партии;
  интернет-цена «Интернет цена (Сокол)» по пустой характеристике, приоритетнее.

================================================================================
4. ЗАГРУЗКА ЗАКАЗОВ
================================================================================

Процедура: ЗагрузитьЗаказыБУС → ЗагрузитьЗаказыJSON.
Нужны: Магазин, ВладелецКаталога, Город, Соединение, ор_ИдентификаторКаталога.

4.1. Получение пакета

Метод: POST HTTPS
URL:   https://{домен}/local/tools/1c_exchange/as_order_exchange.php
Заголовки: JSON + Bearer (см. §1.1)

Тело:
{
  "city": "<город узла, напр. moscow>",
  "micro_point_id": "<ИдентификаторКаталога>"
}

Успех: JSON-массив заказов. Пустой массив = нет заказов, это норма.

Загружаются ТОЛЬКО заказы со status.id = "N" (ЭтоНовыйЗаказ).
Остальные элементы массива пропускаются.

4.2. Структура элемента массива (поля, которые читает модуль)

Корневые:
  id              номер заказа на сайте → ЗаказПокупателя.НомерЗаказаНаСайте
                  (пробелы и НПП вырезаются)
  createdAt       дата; парсер Фрм(...,"дата") ждёт ДД.ММ.ГГГГ
                  (Лев 2 = день, Сред с 4 длина 2 = месяц, Прав 4 = год).
                  Пример в комментарии "2023-11-07 10:07:40" этим парсером
                  не разбирается → подставляется ТекущаяДата().
  isCanceled      булево; если заказ уже есть в 1С и isCanceled — закрыть/отменить
  comment         комментарий документа
  totalPrice      сумма заказа (для контроля строк)
  city            город (moscow / spb / biysk) — фильтр по базе в коде закомментирован
  payment_source  строка источника оплаты микросервиса
                  → ор_ИдентификаторКупона (нужен для Атол, не для создания заказа)
  warehouseGuid   есть в комментарии-примере, в разборе НЕ используется

status:
  id    "N" = новый (единственный принимаемый)
  text  не используется

payment:
  isPayed  → оплачен на сайте (фтм_ХарактеристикиИнтернетЗаказа.ОплаченНаСайте)
  id, text не используются

customer:
  name, surname, email, phone
  phone нормализуется: убрать пробел - + ( ), 10 цифр → префикс 7, ведущая 8 → 7

delivery:
  id        "41" или "66" = самовывоз (эвСпособДоставки=0), иначе доставка (=1)
  price     стоимость доставки (для не-самовывоза)
  date      дата доставки, формат ДД.ММ.ГГГГ → ЖелаемаяДатаПродажи / ДатаОтгрузки
  address   адрес доставки
  text      в код не пишется
  pointGuid точка самовывоза (фильтр по складу в коде закомментирован)

basket[]:
  xmlId     идентификатор номенклатуры:
            длина < 15 → поиск по коду справочника;
            иначе попытка UUID → ПолучитьСсылку(УИД)
  quantity  количество
  price     цена
  name      в содержание строки
  productId есть в примере, в коде НЕ читается
  эвИдПозиции необязательно (общее поле загрузчика строк)

Пример из комментария модуля:
[
  {
    "id": 311816,
    "createdAt": "2023-11-07 10:07:40",
    "updatedAt": "2023-11-07 10:07:40",
    "isCanceled": false,
    "status": { "id": "N", "text": "Принят, в сборке" },
    "payment": { "isPayed": false, "id": "13", "text": "Наличными" },
    "basket": [
      {
        "productId": "250117",
        "xmlId": "bx_6549e1b62b3ca",
        "name": "АТЕРОКЛЕФИТ 100МЛ ЭКСТР. ЖИДК. Д/ПРИЕМА ВНУТРЬ",
        "quantity": 1,

      }
    ],

4.3. Логика загрузки в 1С

Для каждого заказа с status.id = "N":
  1) Поиск ЗаказПокупателя по НомерЗаказаНаСайте = id.
  2) Если найден:
       при isCanceled — закрыть заказы, состояние доставки «Отменен»;
       в список подтверждения id всё равно попадает;
       новый документ не создавать.
  3) Если не найден — создать ЗаказПокупателя:
       Организация = ВладелецКаталога, Магазин = склад узла,
       Склад = Магазин.СкладПродажи,
       эвИсточникЗаказа = предопределённый ЭВАЛАР,
       ИнтернетЗаказ = Истина, УчитыватьНДС = Истина, Статус = Согласован,
       НомерЗаказаНаСайте = id,
       Этикетка = ХранилищеЗначения(весь элемент JSON как Соответствие),
       товары из basket по xmlId;
       если номенклатура не найдена — ЕстьОшибки = Истина (документ всё равно пишется).
  4) Запись, попытка проведения. Ошибка проведения → ЕстьОшибки.

4.4. Подтверждение получения (обязательно после разбора)

Метод: POST
URL:   https://{домен}/local/tools/1c_exchange/as_order_sent.php
Тело:  { "id": "<номер заказа>" }

Ожидаемый ответ-соответствие: STATUS = SUCCESS.
В исходнике успех проверяется как Соответствие и STATUS=SUCCESS;
если тип ответа иной — флаг «заказы загружены» может остаться Истина.

Поштучно по каждому id из загруженных.

4.5. Ошибка загрузки строк → статус на сайт

Если ЕстьОшибки:
  ПередатьСтатусЗаказаБУС(..., "as_status_exchange", "ER")
  см. §5.

5. СМЕЖНЫЕ PHP (не запрашивались, кратко — чтобы не смешать с загрузкой)
================================================================================

База путей: /local/tools/1c_exchange/{команда}.php
Все POST JSON + Bearer.

as_status_exchange
  тело: [ { "id": "<номер>", "status": { "id": "F"|"ER", "text": "text" } } ]
  F  = выполнен (после пробитого чека в исходнике)
  ER = ошибка загрузки
  успех: массив или STATUS=SUCCESS

as_completed_exchange
  тело: { "city": "<город>" }
  загрузка «выполнен с сайта» (доставка). Вне области остатков/приёма заказа.

as_completed_sent
  тело: { "id": "<номер>" }
  подтверждение обработки «выполнен».

as_cancel_order / as_cancel_sent
  в текущем _ВыполнитьОбмен закомментированы.

Коды статусов БУС из комментария модуля:
  N  — принят, в сборке (новый, грузим)
  F  — выполнен (1С → сайт)
  ER — ошибка (1С → сайт)
  FO — отменён (обе стороны, as_cancel_order)

6. СВОДКА HTTP ДЛЯ РЕАЛИЗАЦИИ
================================================================================

Остатки (микросервис, рекомендуется)
  POST http://{host}/amount/{storeId}
  SecureToken + JSON
  [ { "product": "<uuid>", "amount": <int> } ]
  200

Цены (опционально, тот же host)
  POST http://{host}/price/{storeId}
  SecureToken + JSON
  [ { "product": "<uuid>", "price": <num>, "vat_percentage": <num|-1> } ]
  200

Полные и инкрементальные остатки = один метод; дельта собирается в 1С
сравнением учёта со снапшотом фтм_СвободныеОстаткиДляСайта.

Заказы
  POST https://{domain}/local/tools/1c_exchange/as_order_exchange.php
  Bearer + JSON { "city", "micro_point_id" }
  → массив заказов, брать status.id = "N"

Подтверждение заказа
  POST https://{domain}/local/tools/1c_exchange/as_order_sent.php
  { "id": "<номер>" }
  STATUS=SUCCESS

Ошибка заказа (смежно)
  POST .../as_status_exchange.php
  [ { "id", "status": { "id": "ER", "text": "text" } } ]

8. ГОТОВЫЙ БЛОК ДЛЯ ПРОМПТА
================================================================================

Реализуй обмен с БУС Эвалар (сайт asevalar.ru + микросервис остатков).

Остатки. Полная и инкрементальная выгрузка одним HTTP:
POST http://{host}/amount/{storeId}
заголовок SecureToken (секрет из настроек), Content-Type application/json.
Тело — массив порциями ~10:
  [{ "product": "<UUID номенклатуры>", "amount": <целое, 0 если позиция исчезла> }]
Успех HTTP 200. Не слать позиции с ценой 0 при остатке > 0.
Инкремент считать в 1С: свободный остаток склада (минус резерв) vs снапшот
последней успешной отправки; в пакет — изменившиеся, новые и обнулившиеся.
После 200 обновить снапшот. Полная выгрузка — тот же POST, но все позиции
с остатком и все обнуления снапшота.
Опционально POST /price/{storeId} тем же токеном:
  [{ "product", "price", "vat_percentage" }].

Заказы. HTTPS к домену БУС.
Authorization: Bearer {token}, Content-Type application/json.
1) POST /local/tools/1c_exchange/as_order_exchange.php
   тело { "city": "moscow|spb|biysk", "micro_point_id": "<storeId>" }
   ответ — массив. Импортировать только status.id = "N".
   Поля: id, createdAt, isCanceled, comment, totalPrice, city, payment_source,
   payment.isPayed, customer.{name,surname,email,phone},
   delivery.{id,price,date,address,pointGuid},
   basket[].{xmlId,quantity,price,name}.
   xmlId: короткий — код номенклатуры, иначе UUID.
   delivery.id 41 или 66 = самовывоз, иначе доставка.
   Идемпотентность по id. Если заказ есть и isCanceled — отменить, не создавать.
2) По каждому принятому id: POST /local/tools/1c_exchange/as_order_sent.php
   { "id": "<номер>" }, ждать STATUS=SUCCESS.
3) Если строки не сопоставились: POST /local/tools/1c_exchange/as_status_exchange.php
   [{ "id": "<номер>", "status": { "id": "ER", "text": "text" } }].

Не смешивать с АСНА/Мегааптекой. Токены и host брать из настроек, не из хардкода.
